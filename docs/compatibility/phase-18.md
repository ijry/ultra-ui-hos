# 阶段 18 兼容说明

阶段 18 增加 `UPQrcode`、`UPBarcode`、`UPRowNotice`、`UPColumnNotice` 与 `UPNumberKeyboard`，补齐二维码、条形码、横向公告、纵向公告与数字键盘五类能力。五个组件均面向 HarmonyOS NEXT API 24 使用原生 ArkUI 实现，并从 `@lingyun/ultra-ui-hos` 公共入口导出。

## 范围

- `UPQrcode` 复刻上游二维码：`UPQrcodeEncoder` 是完整的 QR 编码器，公开 `getModuleCount()`/`getTypeNumber()`/`getTotalDataCount()`/`isDark()`，内部 `resolveType/createData/createBytes/makeImpl/setupProbe/setupAdjust/setupTiming/setupTypeNumber/setupTypeInfo/mapData/lostPoint/createQrcode` 与上游 `QRCode` 一一对应，`UPQrcodeGaloisField`（单例 `UP_QRCODE_FIELD`）、`UPQrcodePolynomial` 与 `UPQrcodeBitBuffer` 承担 RS 纠错运算，`UP_QRCODE_PAD0 = 0xEC`、`UP_QRCODE_PAD1 = 0x11`、`UP_QRCODE_ERROR_CORRECT_LEVEL = [1, 0, 3, 2]`、`UP_QRCODE_G15`/`UP_QRCODE_G18`/`UP_QRCODE_G15_MASK`、`UP_QRCODE_PATTERN_POSITION_TABLE` 与 `UP_QRCODE_RS_BLOCK_TABLE` 全部保持上游取值，`upQrcodeUnicodeFormat8()`/`upQrcodeUtf8Bytes()`/`upQrcodeBchTypeInfo()`/`upQrcodeBchTypeNumber()`/`upQrcodeMaskAt()` 同样按上游算法输出，八种掩码取罚分最小者。绘制侧 `draw()` 逐格 `fillRect` 铺色，`upQrcodeForeground()` 复刻 `getForeGround()`：`foreground` 铺满码格，`pdground` 只作用于三个定位角内核；`quietZone` 按 `Math.max(0, Math.floor(...))` 钳制并加进渲染矩阵；`icon` 走 `drawRoundedRect()` 先铺圆角底衬再叠图；`lv` 经 `upQrcodeLevel()` 钳制到 0–3，越界回落 3（H）；`size` 与 `unit` 经 `upCanvasParseSize()` 换算，`useRootHeightAndWidth` 打开时由 `onAreaChange` 取根节点短边（等价上游 `setNewSize()`）；`cid` 缺省时由 `upQrcodeId()` 生成上游同形的随机 canvasId；`showLoading` 打开时叠一层 `UPLoadingIcon` 蒙层（`loadingText` 默认「生成中」）；`onResult`/`onPreview`/`onLongpress`/`onError` 对齐上游四个事件，命令式 `clear()` 清屏后回传空串。
- `UPBarcode` 复刻上游条形码：`UP_BARCODE_FORMATS` 保留上游校验白名单（`auto`、`CODE128`/`CODE128A`/`CODE128B`/`CODE128C`、`EAN13`/`EAN8`/`EAN5`/`EAN2`、`UPC`/`UPCA`/`UPCE`、`CODE39`、`ITF`/`ITF14`、`MSI`/`MSI10`/`MSI11`/`MSI1010`/`MSI1110`、`pharmacode`、`codabar`），`upBarcodeFormatSupported()` 负责判定；`upBarcodeCode128()`（`UP_BARCODE_CODE128_START_B = 104`、`UP_BARCODE_CODE128_STOP = 106`、`upBarcodeCode128Pattern()` 越界返回空串）、`upBarcodeCode39()`、`upBarcodeEan13()`、`upBarcodeEan8()`、`upBarcodeEan52()`、`upBarcodeUpca()`、`upBarcodeUpce()` 分别产出模块串，校验位与位数错误经 `UPBarcodeEncodeResult.error` 回传。绘制侧按总模块数摊平宽度，`displayValue` 控制文本行，`textPosition` 支持上游 `top`/`bottom`，`textAlign` 经 `upCanvasTextAlign()` 映射，`textSize()` 复刻上游 `fontSize || 20` 的兜底（0 与空串落到 20），`marginTop`/`marginBottom`/`marginLeft`/`marginRight` 各自缺省时回落 `margin`，`calculateCanvasSize()` 的「宽度不低于 100、高度不低于 `60 + textHeight`」同样保留。`onRendered` 保持上游两种形态：`useCanvas` 为真时回传 `type: 'canvas'` 与 `canvasId`，为假时回传 `type: 'image'` 与图片数据。
- `UPRowNotice` 复刻横向公告：滚动改用原生 `Marquee({ start, step, loop: -1, fromStart: true, src })` 并配 `marqueeUpdateStrategy(MarqueeUpdateStrategy.DEFAULT)`、`allowScale(false)`，`upRowNoticeStep()` 把上游「每秒像素」按 `UP_ROW_NOTICE_FRAMES_PER_SECOND = 60` 折算成每帧步长，`upRowNoticeSpeedPx()` 复刻上游 `getPx()`（数字按 px，`rpx`/`upx` 按 375 设计稿折算，非法值回落 80），`upRowNoticeDuration()` 保留上游 `textWidth / speed` 的时长契约。`upRowNoticeSlices()` 复刻上游 `innerText()` 的 `UP_ROW_NOTICE_SLICE_LENGTH = 20` 字符分片。`text` 变化时 `restart()` 先停后开（`setTimeout` 10 毫秒，等价上游 `paused → running`），`aboutToDisappear` 清理定时器。左侧图标取 `icon`（默认 `volume`），`mode` 为 `link` 时右侧渲染箭头、为 `closable` 时渲染关闭图标并回传 `onClose`，整行点击回传 `onClick`。
- `UPColumnNotice` 复刻纵向公告：轮播改用原生 `Swiper`，`autoPlay(true)`、`indicator(false)`、`loop(true)`、`vertical(step ? false : true)`、`disableSwipe(disableTouch)`、`interval(duration)` 与上游属性逐条对齐，`onChange` 复刻上游 `noticeChange()` 并把索引带进 `onClick`。`upColumnNoticeItems()` 归一化上游「声明为数组、默认值却是空串」的 `text`：数组逐项转字符串，单值按一条兜底，空值渲染 `UP_COLUMN_NOTICE_SWIPER_HEIGHT = 16` 的占位行。`interval()` 用 `Math.max(100, ...)` 兜底非法时长（默认 1500），`justifyContent` 覆盖上游 `center`/`flex-end`/`space-between`/`space-around`/`space-evenly` 并映射到 `FlexAlign`，缺省为 `FlexAlign.Start`；每条公告单行省略号截断。
- `UPNumberKeyboard` 复刻数字键盘：`upNumberKeyboardKeys()` 复刻上游 `numList` 的分支（`card` 为 1–9 + `UP_NUMBER_KEYBOARD_CARD_X` + 0，`dotDisabled` 为 1–9 + 0，否则 1–9 + `UP_NUMBER_KEYBOARD_DOT` + 0），`upNumberKeyboardShuffle()` 复刻 `randomArray()` 的洗牌且不改动源数组，`upNumberKeyboardWideKey()` 复刻 `itemStyle()` 让非乱序数字键盘中 index 为 9 的 0 键占两格，`upNumberKeyboardGrayKey()` 保留上游 `btnBgGray()` 的同名判断，`upNumberKeyboardModeSupported()` 声明 `number`/`card` 两个有效 mode。按键取 `222rpx × 90rpx`（宽键 `464rpx`）、圆角 4、白底、20px Medium `#303133`，退格键底色 `rgb(200, 202, 210)` 配 28 号 `backspace` 图标，根容器 `Flex` 换行居中并铺 `rgb(224, 228, 230)` 底色。`onChange` 复刻上游 `keyboardClick()` 的取值语义（允许小数点时非 `.`/`X` 的按键转成数字），`onBackspace` 先触发一次再按 `UP_NUMBER_KEYBOARD_BACKSPACE_INTERVAL = 250` 毫秒连续触发，抬起、取消与 `aboutToDisappear` 都会清理定时器。

## 边界

ArkTS 禁止索引签名与 `any`，因此上游 `v-for` 里裸用 index 的写法改为具名模型：`UPNumberKeyboardKey { index, label }` 承载一枚按键，`UPNumberKeyboardChangeEvent { value, text }` 同时回传上游 emit 的原值与按键文本，`UPBarcodeEncodeResult { pattern, error }` 与 `UPBarcodeRenderedEvent { type, id, value, path }` 分别承载编码结果与 rendered 载荷；`UPColumnNotice` 的 `text` 用 `UPRawValue | Array<UPRawValue>` 显式声明两种入参形态。

以下上游能力保留为 no-op 兼容位或改由宿主承担，除改名项外都会在传入时通过 `UPCompatibilityDiagnostics.report()` 记录一条诊断：

- `UPQrcode` 的导出：`toTempFilePath` 不可用，`onResult`/`onLongpress` 回传 base64 data URL 而不是临时文件路径，导出失败回传 `onError`（「二维码导出失败」）；`allowPreview` 打开时 `uni.previewImage` 同样不可用，点击只把 data URL 交给 `onPreview`，`saveImageToPhotosAlbum` 不复刻，落盘与相册写入由宿主负责；`val` 为空时上游弹 `uni.showToast`，本端改为回传 `onError`（「二维码内容不能为空」）；`show` 在上游只声明不消费，本端保持画布始终渲染；`unit` 只支持 `px`/`rpx`/`upx`，其余取值回落 `px`；`usingComponents` 是上游的编译期开关，在 ArkUI 上是 no-op；`icon` 只绘制本地地址（`resource://`、`file://`、`/`、`$rawfile:`），远端地址被跳过。
- `UPBarcode` 的 `useCanvas`：关闭时上游走 `toTempFilePath` 落临时文件，本端在 `onRendered` 里回传 base64 data URL，导出失败回传 `onError`（「生成条码图片失败」）；`font` 与 `fontOptions` 在上游从未写入画布上下文，因此只有 `fontSize` 生效，其余取值是 no-op；白名单内但上游 `switch` 无分支的格式（`CODE128A`/`CODE128B`/`CODE128C`、`ITF`/`ITF14`、`MSI` 系列、`pharmacode`、`codabar`）与白名单外的取值一样按 CODE128 编码，与上游落到 `default` 的行为一致；`canvasId` 只作信息透传，ArkUI 通过渲染上下文寻址画布。
- `UPRowNotice` 的 `speed`：CSS 关键帧时长改为原生 `Marquee` 的步进，由 `upRowNoticeStep()` 换算，滚动节奏与浏览器实现存在细微差异；`bgColor` 在上游 `u-row-notice` 内从未落色，保持 no-op，需要底色请用 `customStyle` 覆盖；文本宽度改由 `upCanvasEstimateTextWidth()` 估算（ArkUI 无 DOM 量测），`upRowNoticeDuration()` 因此只保留时长契约；`text` 传非字符串时按 `String()` 兜底。
- `UPColumnNotice` 的 `speed`：上游为纵向模式声明了 `speed` 却从未读取，本端同样保持 no-op；`bgColor` 与横向公告一致保持 no-op；`Swiper` 的自动轮播由原生实现驱动，上游基于 CSS 过渡的切换观感不完全一致。
- `UPNumberKeyboard` 的 `hover-class`：`u-hover-class` 与 `hover-stay-time` 在 ArkUI 无对应能力，按下态改由 `onTouch` 落一层 `#bbbcc6` 背景近似；`mode` 取值不在 `number`/`card` 内时上游 `numList` 无分支并渲染空键盘，本端回落数字键盘布局并记录诊断；上游 `btnBgGray()` 在模板中未被使用，`upNumberKeyboardGrayKey()` 只对外暴露同名判断而不参与渲染。

五个组件只使用 ArkUI、本地状态和宿主回调，不使用 WebView、网络请求、运行时 JSON、Vue/NVue 或业务路由。二维码与条码图片的落盘、相册写入与分享，公告栏点击后的页面跳转，以及键盘输入值的拼接与校验仍由宿主负责。

## 验证

- 最低兼容 API：24；产品兼容/目标 SDK：`5.0.0(12)`。
- 阶段 18 静态契约覆盖五个组件的默认值与常量、核心 Props/事件、二维码编码器与纠错级别顺序、条码格式白名单与文本位置、`Marquee` 步进与公告分片、`Swiper` 轮播与对齐映射、键盘布局分支与退格间隔、公共导出、`Components V` 目录和五条 Demo 路由。
- 二维码编码器与上游 36 组样例逐格比对一致（内容、容错级别与版本矩阵三者组合）。
- HAR（`ultra_ui.har`）与示例 HAP（`entry-default-unsigned.hap`）已通过 `./scripts/build.sh` 完成 ArkTS 编译与打包，字体资源契约通过。
- 未连接 HarmonyOS 模拟器或真机时，设备验证结果记录为 `skipped`；静态契约通过不等于设备验证通过。当前未宣称二维码与条码的扫码可读性、公告栏滚动跟手度与轮播节奏、数字键盘长按连续退格手感的设备验证完成；这些表现需在真机复核。
